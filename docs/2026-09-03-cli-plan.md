# Notes CLI plan (2026-09-03)

A plan for making every feature of Notes usable from a terminal by anyone who installs the app, with no other software on their machine. Written after a research pass over how Electron apps ship CLIs (VS Code, Obsidian 1.12, Joplin, Logseq, 1Password), how note-taking CLIs are designed (nb, zk, jrnl, the official Obsidian CLI, gh), the Windows mechanics of a GUI app with a console entry point, Node CLI tooling in 2026, and how a CLI coordinates with a running desktop app — plus a spike on this machine that settled the one question the sources disagreed on.

## Goal

`notes` works in cmd, PowerShell and Windows Terminal right after installing Notes:

```
notes new "Shopping" --content "- [ ] milk"
echo "call the bank" | notes inbox
notes list --tag wow --json | jq '.[].title'
notes show "WOW PRIVATE SERVER - COMMANDS" | less
notes edit shopping            # $EDITOR
notes export shopping --png -o shopping.png
notes trash restore 3f2a
notes open shopping            # brings up the window at the note
```

Every feature of the app has a command. Output is human-friendly in a terminal and machine-friendly when piped. Scripts get JSON and real exit codes. Nothing the CLI does can lose what someone is typing in the window at the same moment.

## What the research decided

**1. The CLI runs on the app's own Electron binary as Node, the way VS Code's `code` does.** Electron honours `ELECTRON_RUN_AS_NODE=1` and becomes a plain Node 24 runtime (Electron 43 carries Node 24.18). VS Code's entire CLI is a batch file that sets that variable and runs `Code.exe cli.js %*`. This costs zero extra megabytes, needs no Node on the user's machine, and keeps one version number. The spike on this machine with Electron 43.3.0:

| mode | stdout piped / captured | exit code through a `.cmd` shim | stdin | cold start |
|---|---|---|---|---|
| GUI exe handling a `--cli` flag in the main process | works | works | **empty** — stdin never arrives | 90–175 ms |
| `ELECTRON_RUN_AS_NODE=1` + `cli.js` | works | works | works | ~100 ms |
| plain `node -e` for comparison | — | — | — | ~40 ms |

A notes CLI without stdin (`echo x | notes inbox`, `notes new -`) is not a notes CLI, so the GUI-exe-with-a-flag design is out. (The claim in older sources that a GUI-subsystem Electron exe cannot have its output piped is no longer true: Chromium leaves stdout alone when it is already a valid handle. It only matters that stdin does not work.)

**The price is the `RunAsNode` fuse.** `forge.config.ts` currently sets it to `false`, on Forge's template advice. Electron's own statement on the "run as node" CVEs rates the risk as not critical: an attacker "needs to already be able to execute arbitrary commands on the machine", and the concern is a compromised machine using the signed app binary as a Node runtime that inherits the app's permissions. VS Code, Slack and Obsidian all ship with it enabled for exactly this reason. Notes holds no OS-granted permissions worth inheriting. Decision: flip `RunAsNode` to `true`, keep `EnableNodeOptionsEnvironmentVariable` and `EnableNodeCliInspectArguments` off (so the runtime cannot be told to load foreign code through the environment), and say so in the README.

Rejected alternatives: a Node single-executable (50–115 MB, needs its own signing, pkg/nexe-style binaries are routinely flagged by Defender), Bun/Deno compiles (a second runtime), an `npm i -g` package (needs Node, so not "anyone"), and a `notes://` URI as the only interface (no return value, 2 kB limit; it is worth adding later as a launcher, not as the CLI).

**2. Two ways to reach the notes, chosen automatically.** The store is a folder of markdown files, and the app already watches that folder and applies external changes. So:

- *App not running:* the CLI reads and writes the files itself, through the same store code the main process uses. Nothing to start, ~100 ms.
- *App running:* the CLI connects to it and the app performs the operation. This is the only way to open the window at a note, use the quick-note box, render a PNG (that needs a BrowserWindow), read what the user is typing right now, or change hotkeys — and it makes the app the single writer, so a CLI write can never race the 300 ms autosave.

This is apple-notes-cli's split and Obsidian's official CLI's model (which requires the app and auto-launches it) combined; Joplin's Data API and 1Password's `op` are the precedents for "the CLI asks the running app".

**3. The transport is a named pipe, the protocol is newline-delimited JSON-RPC 2.0.** Named pipes on Windows are removed when the owning process dies, so there is no stale-socket problem; `FILE_FLAG_FIRST_PIPE_INSTANCE` means a second `listen()` fails instead of hijacking; the default DACL lets only the owner and administrators connect duplex. `AF_UNIX` is unusable from Node on Windows (libuv support unmerged as of 2026). A localhost TCP port would be reachable by any local process and by web pages via DNS rebinding, which is why Joplin and Obsidian's REST plugin need tokens and origin checks. VS Code uses exactly this pipe design, named from a hash of the userData path. Electron's own `second-instance` channel cannot reply (the ack API was added and then removed) and mangles argv on Windows, so it is used only as "wake up and focus", never for data.

**4. The command grammar follows nb, zk, gh and the official Obsidian CLI.** Noun-verb where there is a noun (`notes trash restore`, `notes history list`), top-level verbs for the daily ones (`new`, `list`, `show`, `edit`, `append`, `inbox`, `search`, `delete`, `open`), one filter grammar shared by every command that takes a set of notes, several ways to name a note resolved in a fixed order, the body from argv / stdin / `--file` / `$EDITOR`, and three output modes chosen by whether stdout is a terminal (pretty, tab-separated, `--json`). Exit codes are real; the Obsidian CLI's "exits 0 on error" is the widely criticised mistake to avoid.

**5. Parser: commander 15** (ESM-only, zero dependencies, ~18 ms startup, help groups, `exitOverride` + `configureOutput` for in-process tests, ~50 M weekly downloads). Colour via Node's built-in `util.styleText` (honours `NO_COLOR`/`FORCE_COLOR`, no dependency). Prompts and the fuzzy note picker via `@inquirer/prompts` (`search`, `confirm`, `editor`); `$EDITOR` via `@inquirer/external-editor` with `postfix: '.md'`. Shell completion for PowerShell, bash, zsh and fish via `@bomb.sh/tab`, which integrates with commander and is what Cloudflare, Nuxt, Astro and Vitest use. `--jq` via `jq-wasm` only if it earns its 1 MB; `--fields` first.

## Architecture

```
src/
  core/            NEW  pure Node, no Electron, no DOM: everything the CLI and main share
    paths.ts            userData/notes/trash/history/attachments dirs from an injected root
    store.ts            <- src/main/notes-store.ts with app.getPath replaced by paths
    history.ts          <- src/main/history-store.ts, same change
    settings.ts         <- src/main/settings.ts, same change
    attachments.ts      <- the file half of src/main/attachments.ts (save bytes, sweep)
    query.ts            the shared filter grammar (terms, #tag, --pinned, --created-after, --links-to...)
    resolve.ts          note identification: id -> exact title -> unique title prefix -> filename -> fuzzy
    ipc-protocol.ts     method names, param/result types, error codes (shared by client and server)
  shared/          as now (notes-folder, history rules, keys, settings shape, assets, types)
  renderer/        as now; notes.ts, find.ts, outline.ts, tasks.ts, fences.ts, plaintext.ts, importer.ts
                   are already pure and are imported by the CLI as they are
  main/            Electron only: windows, tray, capture, context menu, PNG export, IPC handlers,
                   and NEW ipc-server.ts (the named pipe) + squirrel.ts (install hooks, shim, PATH)
  cli/             NEW
    index.ts            entry: commander program, global flags, output mode, error -> exit code
    commands/*.ts       one file per noun or top-level verb
    client.ts           connects to the pipe (or spawns the app), falls back to core/ when allowed
    output.ts           pretty / tsv / json rendering, styleText, tables without borders
    editor.ts           $VISUAL/$EDITOR round trip
bin/
  notes.cmd, notes.ps1  written into %LOCALAPPDATA%\Notes\bin at install/update time (templates live in assets/)
```

Build: a fourth Vite build entry in `forge.config.ts` (`src/cli/index.ts` → `.vite/build/cli.js`, target node, single bundled file, `marked` and friends bundled in, Electron externals not allowed). The renderer, main and preload builds are untouched. `markdown.ts` (DOMPurify) stays out of the CLI; `notes render --html` in file mode uses `marked` alone with the same extensions, and in app mode asks the app.

### The shim and PATH

`%LOCALAPPDATA%\Notes\bin\notes.cmd`:

```bat
@echo off
setlocal
set ELECTRON_RUN_AS_NODE=1
set ELECTRON_NO_ATTACH_CONSOLE=
call "%~dp0current.cmd"
"%NOTES_APP%\Notes.exe" "%NOTES_APP%\resources\app.asar\.vite\build\cli.js" %*
exit /b %ERRORLEVEL%
```

`current.cmd` holds one line, `set "NOTES_APP=C:\Users\...\AppData\Local\Notes\app-0.12.0"`, rewritten by the app on every `--squirrel-install` and `--squirrel-updated` event (Squirrel runs the new exe with those flags and waits up to 15 s). Resolving the version folder this way avoids the two traps: the root stub `Notes.exe` returns exit code 0 immediately without waiting, and alphabetical `dir` sorts `0.9` after `0.10`. `notes.ps1` is the PowerShell twin (npm's cmd-shim shape: `$input | & exe $args; exit $LASTEXITCODE`) so piping from PowerShell keeps stdin.

PATH: on the same Squirrel events, read `HKCU\Environment\Path` with `reg query` (never `setx`, which truncates to 1024 characters, and never `[Environment]::SetEnvironmentVariable`, which demotes `REG_EXPAND_SZ` to `REG_SZ`), append the expanded `bin` path if `;path;` is not already contained, write back with `reg add /t REG_EXPAND_SZ`, then broadcast `WM_SETTINGCHANGE "Environment"` via a one-line PowerShell `SendMessageTimeout` so new terminals see it. Remove the entry on `--squirrel-uninstall`. The same code backs a `notes cli install` / `notes cli uninstall` command and an "Install the `notes` command" row in the Layout sheet, like Obsidian's toggle, for people who installed from the zip.

### The IPC server (main process)

- Pipe name `\\.\pipe\notes-<sha256(userData)[0:8]>-v1`; `net.createServer` with default options (never `readableAll`/`writableAll`, which grant Everyone).
- After `listen()`, write `<userData>\ipc.json` `{ pipe, pid, token, version, protocol }`; the token is 32 random bytes per launch. Delete it on `will-quit`.
- Protocol: one JSON object per line, JSON-RPC 2.0. First message must be `hello { token, cliVersion }` → `{ appVersion, protocol }`; anything else on an unauthenticated connection closes it. Methods are the operations in the table below, prefixed by noun. Long operations (PNG export, import of many files) send `progress` notifications before the result. Errors carry `data.exit` so the CLI maps them to exit codes without guessing.
- The server calls the same functions the renderer's IPC handlers call, and for anything that needs the renderer (the live body of the open note, `open`, `capture`, UI toggles) it round-trips over the existing `ipcMain`/`webContents.send` channels with a request id.
- `note.status(id)` returns `{ dirty, updatedAt, hash }` from the renderer, so the CLI can refuse to overwrite a note that is being typed in unless `--force` (which flushes autosave first).

### The client (CLI)

1. Read `ipc.json`; if present and `process.kill(pid, 0)` succeeds, connect (ENOENT means the app died without cleaning up — fall through).
2. If not connected and the command does not need the app: run in file mode through `core/`. Writes are tmp + fsync + rename in the same directory, with a bounded retry on `EPERM`/`EBUSY` (antivirus and the indexer hold files briefly on Windows). The app's watcher sees the change within 700 ms and applies it, exactly as it does for a sync tool.
3. If the command needs the app (`open`, `capture` box, `export --png`, `ui`, `hotkeys`, `note.status`): spawn it detached (`Update.exe --processStart Notes.exe --process-start-args "--from-cli"` when packaged, `process.execPath` in dev), `stdio: 'ignore'`, `ELECTRON_NO_ATTACH_CONSOLE=1`, and poll the pipe every 100 ms for up to 15 s.
4. `--no-app` forces file mode (scripts that must not launch a window); `--app` forces app mode; `--wait` on `open`/`edit` blocks until the note is closed or saved, VS Code style, through a `note.closed` notification.

## Command surface

Global flags: `--json`, `--plain` (tab-separated, no colour), `--fields a,b`, `--no-color`, `-q/--quiet`, `-y/--yes` (skip confirmations), `--no-input`, `--no-app`, `--app`, `--user-data-dir <dir>` (parity with the test harness), `-h` anywhere, `-V/--version` (prints CLI, app and protocol versions and whether the app is running).

Note selectors, resolved in order: front-matter `id` (full or unique prefix), exact title (case-folded, the same `linkKey` as `[[links]]`), unique title prefix, filename in the notes folder, then a fuzzy match — ambiguous matches list the candidates and exit 3, or open a picker when stdin is a terminal. `-` means "the note named on stdin", so `notes list --plain | fzf | notes show -` works. Every command that takes a set of notes accepts the filter grammar: bare terms (AND, case-insensitive, as the app's search), `-term` (exclude), `"a phrase"`, `#tag` (matches nested children, as the app), `--tag`, `--pinned`, `--untitled`, `--created-after/--before`, `--updated-after/--before`, `--links-to <note>`, `--linked-from <note>`, `--orphan`, `--has-tasks`, `--sort updated|created|title|words[-]`, `--limit n`.

Body sources for `new`/`append`/`replace`: positional text, `--content`, `--file <path>`, stdin when it is not a terminal or `-` is given, `--edit` to open `$EDITOR` (also the default when nothing else is given and stdin is a terminal). Several sources concatenate in that order, as nb does.

| App feature | Command | Mode |
|---|---|---|

## Coordination rules (so nothing is lost)

- App running → the app writes; the CLI never touches a note file. Before a write the CLI calls `note.status`; `dirty: true` → exit 4 unless `--force`, which makes the app flush its autosave first and then apply.
- App not running → the CLI writes with the store's own atomic write; the front-matter `updated` is set, the id kept; renames follow the store's `nameSuits` rule so the app's index agrees when it next loads.
- The app's watcher already ignores its own writes by comparing text against its index; CLI writes look like a sync tool's and are applied the same way. The existing "skip the selected note while dirty" rule stays.
- A conflict that cannot be resolved (app down, but a stale `ipc.json` says otherwise, or a hash mismatch on `--if-unchanged`) writes `<name>.conflict-<yyyymmdd-hhmmss>-cli.md` beside the note, Syncthing style, instead of merging.
- History: `record()` runs in the app after its save; in file mode the CLI records a snapshot through `core/history.ts` under the same 5-minute rule, so a script that rewrites a note still has somewhere to go back to.

## Phases

Each phase ends shipped (version bump, tests, `npm run make`, release, install), as every Notes change does.

**Phase 0 — Seam and proof (0.12.0).** Move the file-backed stores into `src/core/` with an injected root path; the main process keeps working unchanged (its tests are the 266 existing ones plus new core tests that run against a temp folder, which the old Electron-bound modules never had). Add the `cli.js` build entry, flip `RunAsNode`, ship `notes --version`, `notes list`, `notes show`, `notes new`, `notes append` in file mode only, with `--json`/`--plain`. Hand-install the shim into `%LOCALAPPDATA%\Notes\bin` and prove: piping, stdin, exit codes, PowerShell and cmd quoting with spaces and `%`, `NO_COLOR`, 100 ms startup. This is the phase that validates every research claim on the real packaged app.

**Phase 1 — Installed for everyone (0.13.0).** Squirrel hooks: write `bin\notes.cmd`, `notes.ps1`, `current.cmd` on install and update; PATH registry write and broadcast; removal on uninstall; `notes cli install|uninstall|status` and the Layout-sheet row. Verify with a fresh terminal after `Notes Setup.exe`, and after an update from the previous version.

**Phase 2 — The whole file-mode surface (0.14.0).** Everything in the table marked "file": filter grammar, selectors and the picker, `edit` with `$EDITOR`, `inbox`, rename/pin/tags/links/backlinks, delete and trash, history, attach, import, export md/txt, tasks/fence/find/replace, outline, render, stats, paths, settings/hotkeys (write settings.json; applying live hotkeys waits for phase 3), `watch`, completion. Tests: vitest on `core/` and on command parsing with `exitOverride`, execa end-to-end against the packaged build with `--user-data-dir` on a scratch folder, snapshot tests of `--help` with `NO_COLOR=1 COLUMNS=100`.

**Phase 3 — The running app (0.15.0).** `ipc-server.ts`, `ipc.json`, token handshake, the method set, renderer round-trips for `note.status`/live body/`open`/`capture`/`ui`/`run`, spawn-and-wait in the client, `--no-app`/`--app`/`--wait`, `export --png`, live hotkey apply. Verify over CDP that a CLI write while a note is open updates the editor without moving the caret, that `dirty` refusal works, and that killing the app mid-command leaves no partial file.

**Phase 4 — Polish (0.16.0).** `notes://` URI for launchers (`open?id=`, `new?text=`, `inbox?text=`), dynamic completion of titles and tags, `--jq` if wanted, a README "Command line" section generated from the commander definitions, and a version-skew handshake (CLI and app negotiate `protocol`, never hard-fail).

## Risks and open questions

- **Fuse trade-off.** Flipping `RunAsNode` on is deliberate and documented; `NodeOptions` and `NodeCliInspect` stay off. Revisit if Electron ships a scoped alternative (a signed "cli entry" fuse has been discussed).
- **Squirrel's 15 s window** for install hooks: the shim and registry work take well under a second, but the hook must never wait on the app's normal startup.
- **PowerShell argument passing to `.cmd`** re-parses quotes; the `.ps1` twin and `$PSNativeCommandArgumentPassing` behaviour need a test matrix (spaces, `%`, `&`, `"`, empty args). VS Code lives with the same limits.
- **stdin line endings**: Windows pipes deliver `\r\n`; the CLI normalises like the paste handler does.
- **Pipe DACL**: an elevated process on the same machine can connect; the token guards against that and against a future TCP transport. Verifying the peer's PID needs a native addon and is out of scope.
- **PNG export** and UI state are app-only by nature; the plan says so rather than pretending file mode can do them.
- **Two writers**: the design makes the app the single writer whenever it runs. The remaining window is a CLI in file mode racing an app that is starting up; `ipc.json` plus the watcher's settle time cover it, and the conflict-copy rule is the backstop.
- **Version skew** between an old shim and a new app: the shim never encodes a version (it reads `current.cmd`), and the CLI bundle ships inside the app, so they cannot diverge.
